# P12.5.2 IL2CPP, Signing, Installer, And Clean-Machine Gate

Status: engineering gate passed on 2026-07-23; production RC gate remains blocked by external release credentials and isolated-machine evidence.

## Scope

P12.5.2 converts the P12.5.1 Windows baseline into a reproducible Windows x64 IL2CPP release pipeline:

- Align Mono and IL2CPP player identity, mission traversal, and deterministic smoke outcome.
- Apply release texture limits, managed stripping, engine stripping, and IL2CPP Release configuration.
- Stage only the runtime allowlist and reject Burst/debug/backup artifacts.
- Sign staged executables and DLLs, build and sign a bilingual Inno Setup installer, and emit SHA-256 evidence.
- Install, launch, complete all 20 waves, uninstall, and verify file, registry, and PlayerPrefs cleanup.
- Prepare the same validation as a network-disabled Windows Sandbox bundle.

## Toolchain

- Unity: 2022.3.12f1
- Backend: IL2CPP, Windows x64, non-development, LZ4HC
- Managed stripping: Medium
- Engine code stripping: enabled
- IL2CPP compiler configuration: Release
- Installer: Inno Setup 6
- Signing: Windows SDK SignTool, SHA-256; production mode also requires RFC 3161 timestamping

The Windows IL2CPP support module is installed in the matching Unity editor. The pipeline fails instead of falling back to Mono when IL2CPP support is absent.

## Build Slimming

Release texture policy is applied before each build:

- Map surfaces, backdrop, and branding: maximum 2048
- HUD/UI textures: maximum 1024
- Units, effects, props, and remaining runtime art: maximum 512
- Standalone compression: DXT1 for opaque sources and DXT5 for alpha sources
- Mipmaps disabled for 2D sprites

Editor previews moved from `Resources` to `Assets/Editor/Previews`. Branding moved outside `Resources`, and Roslyn compiler assemblies are editor-only. The final stage is an explicit runtime allowlist.

## Runtime Parity

Mono and IL2CPP both load `EmberlineBootstrap`, deploy L01, traverse 20/20 waves, report the same mission identity, and finish with score delta 0. IL2CPP output contains `GameAssembly.dll` and does not contain `MonoBleedingEdge`.

The packaged traversal is a technical release smoke, not a balance result. It uses the explicitly reported `--td-smoke-technical-integrity 1000` assist so packaging validation is independent of autoplay balance and frame-step behavior. P12.4 and P12.5.0 remain the gameplay and economy gates.

## Signing Policy

`tools/td_release_windows.ps1` has two modes:

- `Production`: requires a real code-signing certificate by thumbprint or PFX, requires trusted Authenticode status, timestamps files, and can pass the shipping-signature gate.
- `Test`: creates or reuses a local self-signed certificate and validates the complete signing mechanics. It can pass the engineering gate but can never pass the shipping-signature gate.

The test run signed seven staged PE files plus the installer and generated uninstaller. The expected thumbprint matched throughout installation. Trust remained false by design because the certificate was self-signed.

## Installation Validation

`tools/td_validate_installer.ps1` verifies:

1. Installer signature and expected signer.
2. Silent per-user installation into a fresh root.
3. Required IL2CPP layout and signatures after installation.
4. Full 20-wave technical smoke and runtime identity.
5. Signed uninstaller.
6. Silent uninstall, install-root removal, and uninstall-registry removal.
7. Exact restoration of the pre-test PlayerPrefs registry state.

The current-host clean-root run passed every item.

`tools/td_prepare_sandbox_validation.ps1` packages the installer and validator into a mapped Windows Sandbox workspace. Its `.wsb` disables networking and device redirection, runs the same validator with `-CleanMachine`, writes evidence to the host-mapped output, and shuts down.

## Commands

Engineering pipeline with local test signing:

```powershell
& tools/td_release_windows.ps1 `
  -OutputRoot E:/TD/output/release/p1252 `
  -Version 0.12.5 `
  -BuildNumber 2 `
  -SigningMode Test
```

Production pipeline with a certificate already in the current-user certificate store:

```powershell
& tools/td_release_windows.ps1 `
  -OutputRoot E:/TD/output/release/p1252-production `
  -Version 0.12.5 `
  -BuildNumber 2 `
  -SigningMode Production `
  -CertificateThumbprint <trusted-code-signing-thumbprint>
```

On a host with Windows Sandbox enabled:

```powershell
& tools/td_prepare_sandbox_validation.ps1 `
  -InstallerPath E:/TD/output/release/p1252-production/installer/EmberlineDefense-0.12.5-build2-win-x64-setup.exe `
  -OutputRoot E:/TD/output/release/p1252-production/sandbox_validation_bundle `
  -ExpectedVersion 0.12.5 `
  -ExpectedSignerThumbprint <trusted-code-signing-thumbprint> `
  -RequireTrustedSignature `
  -Launch
```

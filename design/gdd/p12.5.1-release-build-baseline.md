# P12.5.1 Release Build Baseline

## Goal

P12.5.1 turns the Unity project into a repeatable Windows x64 release build with a formal product identity, branded launch assets and a standalone full-mission smoke gate. A build is not accepted merely because Unity produced an executable: the packaged player must boot the production scene, expose the expected runtime identity, complete a real 20-wave mission, preserve late-game economy decisions and exit cleanly.

## Release Identity

- Company: `Emberline`
- Product: `Emberline Defense`
- Application identifier: `com.emberline.defense`
- Semantic version: `0.12.5`
- Build number: `1`
- Bootstrap scene: `Assets/Scenes/EmberlineBootstrap.unity`
- Windows target: x86-64, 1920x1080 native borderless fullscreen with resize and fullscreen switching enabled
- Baseline scripting backend: Mono

`TDReleaseIdentity` is the source of truth used by the bootstrap, editor build pipeline and automated audit. The old `SampleScene`, `DefaultCompany`, `TD` and `1.0` placeholders are no longer release configuration.

## Branding

The Windows player uses the checked-in black-iron rail-defense shield as its application icon. Unity fills all eight Standalone icon sizes from that source and the build wrapper extracts the embedded executable icon as evidence.

The startup background depicts Emberline's defended rail junction in the same black-iron, brass, ember and cyan visual language used by the formal combat UI. Both assets are required build inputs; a missing icon slot or startup background fails the build result.

## Build Command

Run from the workspace root:

```powershell
& 'tools/td_build_windows.ps1' `
  -OutputRoot 'E:/TD/output/builds/p1251_windows' `
  -Version '0.12.5' `
  -BuildNumber 1 `
  -Backend Mono `
  -SmokeTimeScale 16 `
  -SmokeTimeoutSeconds 150
```

The wrapper uses the connected Unity editor through MCP when available and falls back to a hidden Unity batch process when the editor is not running. `-ForceBatchMode` makes the fallback explicit. `-Development` creates a debug build; `-Backend IL2CPP` is supported for later RC validation. Output is restricted to the workspace.

The editor also exposes `TD/Build/Apply Release Player Settings` and `TD/Build/Windows x64 Baseline` for local use.

## Build Gate

The build stage enables strict mode, uses LZ4HC for a non-development player and includes only the production bootstrap scene. `build-result.json` must prove:

- Unity reported success with zero build errors;
- the executable and player data directory exist;
- company, product, application identifier, version and build number match the requested release identity;
- every Standalone icon slot is configured;
- the branded startup background is configured.

## Standalone Smoke Gate

The generated player is launched in a hidden 1280x720 window with `--td-smoke-test`. The probe resets only the disposable smoke campaign profile, then uses the real runtime flow:

1. Load `EmberlineBootstrap` and open Campaign Command on L01.
2. Confirm deployment and start the existing P12.4 adaptive autoplay.
3. Complete all 20 waves through the rendered battle runtime.
4. Require victory and P12.5.0 final-five economy decision value.
5. Reject every runtime error, exception or assertion captured by the probe.
6. Write `standalone-smoke.json` and request a clean process exit with code 0.

The wrapper combines build, identity, branding and smoke results in `p1251_build_audit.json`. `hardPass` is the release-baseline decision.

## Scope Guard

P12.5.1 establishes the deterministic unsigned Mono build baseline. It does not claim RC completion. IL2CPP parity, code signing, installer/store packaging, clean-machine installation, performance and memory soaks, save corruption recovery, crash/analytics transport, legal metadata and final shipping sign-off remain P12.5.2 and later work.

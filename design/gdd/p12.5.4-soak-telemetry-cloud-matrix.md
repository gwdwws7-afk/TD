## Crash And Analytics Transport

`TDReleaseTelemetry` is created before local diagnostics. Its default state is no consent and no collection. `SetPlayerConsent(false)` clears pending telemetry files.

The transport sends only the serialized `TDP1254TelemetryEvent` allowlist:

- Event, build, platform, checkpoint, level/map/wave, and pass/fail context.
- Session and error fingerprints shortened from SHA-256.
- Aggregate soak performance and cloud-matrix row count.

Raw errors, stack traces, filesystem paths, save codes, profile contents, device IDs, email addresses, IP addresses, and credentials are not payload fields. Outside explicit loopback automation, the endpoint must use HTTPS. The production collector URL is injected through release configuration with `--td-telemetry-endpoint`; no production URL or secret is committed to the client source.

Consent-granted events are atomically queued under `Application.persistentDataPath/TelemetryQueue`. The queue is capped at 96 files and 2 MB. A failed request remains queued with exponential retry from 2 to 300 seconds. A 2xx response deletes only the acknowledged item.

Transport coverage includes:

- Clean session start and end.
- Recovery of a prior unclean session.
- Runtime error category and fingerprint.
- Soak summary.
- Cloud-conflict matrix summary.

The packaged Player transport test used a validating HTTP listener, deliberately returned 503 once, then accepted retries:

- Requests: 3
- Planned failures: 1
- Successful uploads: 2
- Queue after retry: 0
- Unexpected fields: 0
- Sensitive-pattern matches: 0
- Final response: 204

The gate temporarily disables the current user's Windows proxy only for the loopback listener test, restores it in `finally`, and records restoration failure as a hard gate failure. Production HTTPS requests continue to honor the player's system proxy.

## Cloud Conflict Matrix

The Player-build audit runs independently for all three campaign slots and restores their prior initialization state and snapshots.

Every row verifies:

1. A local/cloud revision difference is reported as a conflict.
2. `KeepLocal` preserves only the local test clear.
3. `UseCloud` replaces it with the cloud test clear.
4. `Merge` preserves both clears.
5. A payload changed without a new checksum is rejected.
6. A cloud envelope cannot be imported into the wrong active slot.
7. A V1 portable save migrates to the current V2 schema.
8. A future unsupported save version is rejected.
9. Revision remains monotonic through resolution and migration.

Slots 1, 2, and 3 passed every assertion in the IL2CPP Player. The in-process profile restore and the outer registry/persistent-data restore both passed.

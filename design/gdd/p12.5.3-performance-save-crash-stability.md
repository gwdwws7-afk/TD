# P12.5.3 Performance, Save Recovery, And Crash Stability

Status: engineering gate passed on 2026-07-24. The continuous soak, transport, and cloud-conflict follow-up passed in P12.5.4.

## Goal

P12.5.3 makes packaged-player failures observable and recoverable without weakening the existing gameplay gate. It adds local save integrity, automated profile isolation, dense-wave frame and memory evidence, and an unclean-session breadcrumb that survives a forced process termination.

The gate is tied to Windows x64 IL2CPP build 3:

- Product: `Emberline Defense` `0.12.5`
- Backend: IL2CPP Release
- Bootstrap: `EmberlineBootstrap`
- `GameAssembly.dll` SHA-256: `041DD47D2F00CABA7B047F197762CF495DA0F0DB10B2A5E1053E031256AC57EF`

## Save Integrity And Recovery

Every initialized campaign slot now owns:

- A deterministic checksum over its normalized 20-level snapshot.
- A checksummed portable recovery copy in `PlayerPrefs`.
- A primary recovery file under `Application.persistentDataPath/CampaignRecovery`.
- A previous-file fallback retained during atomic replacement.

Recovery order is primary file, previous file, then the `PlayerPrefs` cache. `EnsureInitialized` validates the active slot before normal campaign use and automatically restores a valid snapshot when the local checksum differs. If every recovery source is missing or invalid, the failure is logged as an error so the session diagnostic records it; the game does not silently normalize and overwrite the only evidence.

The recovery audit:

1. Validates the baseline slot and primary recovery file.
2. Changes a valid field to a different in-range value without updating the checksum.
3. Confirms corruption is detected.
4. Calls the real `EnsureInitialized` startup path.
5. Confirms the original snapshot and fingerprint are restored.
6. Confirms a tampered portable recovery payload is rejected.

The L01 packaged smoke and L20 1x/2x/3x rows all passed this audit with `recoverySource=ensure_initialized`.

## Automation Profile Isolation

Before standalone smoke or stability work begins, the probe captures:

- All three campaign slot initialization states and snapshots.
- The active slot.
- The selected campaign level.

The probe restores those values before requesting a clean process exit. The PowerShell gates also export the Windows PlayerPrefs registry key and copy the campaign recovery directory, then restore both in `finally`. This second layer protects the real profile if a test process is terminated before its in-process restore can run.

## Crash Diagnostic

`TDReleaseDiagnostics` writes a five-second session heartbeat containing:

- Session, product, Unity, scene, and checkpoint identity.
- Current level, map, wave, enemies, towers, projectiles, integrity, and budget.
- Peak allocated and reserved memory.
- Last error, stack trace, and error count.
- Clean or unclean shutdown state.

On startup, an unclean prior session is copied into `Diagnostics/Archive`; the archive is capped at 20 records. `tools/td_p1253_crash_recovery_probe.ps1` launches build 3, force-terminates only that process, relaunches the player, and requires the next session to archive the matching dirty session before completing a clean 20-wave smoke.

The forced session `53d38425735441e598c95e12ca79fd89` remained dirty, the next session reported `previousSessionRecovered=true`, the matching archive exists, the recovery smoke passed, and both in-process and external profile restoration passed.

The implementation currently provides durable local diagnostics. Upload, consent, retry, privacy filtering, and production analytics/crash transport are not part of this phase.
